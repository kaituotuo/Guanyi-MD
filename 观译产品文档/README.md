# 观译产品文档

从 2026-11-15 起，观绎 MD 的大型、复杂功能按“产品方案 → 可交互原型 → 评审 → 开发 → 验收”推进。该目录沿用用户创建的“观译产品文档”命名；新原型按设计系统使用“观译阅读器”命名，旧原型中的“观绎 MD”仅作为历史标识。

## 目录约定

- `1#产品方案/`：需求、现状证据、交互契约、状态与异常、技术边界、开发阶段和验收标准。
- `2#原型/`：可独立打开的交互原型、使用说明、走查记录和参考素材。
- 新功能的同名方案与原型互相链接，保留版本、日期和评审状态。
- 参考图和外部文档用于分析，不视为对功能范围或外部操作的授权。

## 工作流程

1. 阅读现有实现，区分用户确定的需求、当前能力和设计建议。
2. 先写方案，明确常态、加载、失败、取消、恢复以及对既有工作流的影响。
3. 制作能真实操作主要路径的原型；演示数据和模拟行为必须标明。
4. 走查交互与布局，记录已验证内容、尚未验证内容和需要评审的选项。
5. 方案和原型的主要方向评审后，再按里程碑修改产品源码。
6. 开发后按验收矩阵验证真实服务与数据链路；另按项目发布闸门决定打包。

方案阶段的模拟请求不等于真实服务接通；原型通过不等于功能已经开发或发布。

## v0.7 本轮提案

PDF 翻译原型在同一 PDF 阅读器中新增“任务内翻译工具栏”层级：左侧保留 1.0.45 已有目录、查找、批注、智能研读和批注 PDF 另存，随后放置源语言 → 目标语言、划词翻译、全文翻译、原文/对照/译文、历史、菜单、缩小/比例/放大，以及最右侧的“保存译文 PDF”。移除“AI 翻译增强”；不建立独立全文翻译模式。启动全文翻译后自动进入对照视图，点击原文可回退，取消仅停止进行中的任务；桌面与窄屏均保持单行，窄屏仅在工具栏内横向滚动。功能操作统一为 SVG 图标按钮，包括“保存译文 PDF”；悬停与键盘聚焦显示功能名称，控件保留 `title`、`aria-label` 及状态语义，语言、页码与缩放比例继续直接显示。参考素材仅用于布局分析，不嵌入产品。当前总原型版本为 v0.7。


交互原则：任务状态与视图状态分离；状态在阅读状态条中持续可见，进度与失败就近反馈；保存按钮保持稳定位置，未完成时只按需披露禁用原因（`aria-describedby`、悬停或键盘聚焦），完成后直接启用；工具栏始终单行，窄屏仅在工具栏内部横向滚动，并保持键盘可达。模型切换位于顶部“…”菜单的一级菜单项，不占用主页或 PDF 工具栏的主操作位置。

顶部移除主页左侧的全局侧栏切换按钮，主页文件夹栏仍保留；PDF 目录与文档大纲由各自工具栏图标控制。Markdown/TXT/EPUB 阅读区移除重复的“返回主页＋文档标题＋路径”整行，统一通过顶部主页与文档页签导航；批注和更多操作并入文档工具栏。

## v0.1 主页与 AI 对话提案

AI 对话属于主页中的一个工作流，不建立独立工作台。顶部主页标签、对话左上角主页按钮和文档页签共同提供明确返回路径；空状态、消息流、来源 chip、生成中/停止和回答级导出均已在独立原型中演示。页面收敛为一次表达一个事实，去掉重复的“AI 对话”“自由对话 · 未关联文档”“使用下对话能力”和“继续这次思考”。
