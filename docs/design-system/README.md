## 0. 如何使用这份规范

1. 新原型和前端改动开始前，先读本文件，再看 `index.html` 的可视示例。原型页顶部注明“依据：观译阅读器设计系统 V1.0”及产品场景；旧原型只是历史参考，不自动成为新基线。
2. `css/app.css` 是通用运行时 token 与组件尺寸的事实来源；主页、PDF 研读和 EPUB 阅读还需核对 `css/home-workspace.css`、`css/pdf-study.css`、`css/epub-reader.css`；本文件是设计与交互决策的基线；可视手册演示这些规则。三者出现差异时，先核实实际生效样式，再在同一次改动中修正实现与文档。不要直接改同步产物 `index.html` 来定义新规范；运行 `node tools/sync-single-file.mjs` 更新它。
3. 下文标为**现行**的值来自当前前端；标为**V1 约定**的是从现状归纳出的后续设计要求，可能尚未被所有旧页面实现。改变基线时记录原因、影响场景、明暗两套表现及版本变更。
4. 用户内容、文档格式和操作状态优先于视觉装饰。新功能先复用现有语义 token、图标、反馈和布局，再扩充系统。

## 1. 产品表达

**定位。** 观译阅读器是本地优先的阅读、摘录、编辑和批注工作台。品牌 slogan 固定为“俯仰观物，译述我心”，属于产品文案基线；只有用户明确授权时才可修改。顶部字标用“观译”，完整产品名用“观译阅读器”。“观绎 MD”出现在旧原型和旧文档中，不再作为新界面的默认命名。Markdown 是可编辑的核心工作区；TXT、PDF、EPUB 共享文档列表和页签，但工具栏要随格式切换。

**气质。** 暖纸色承载长时间阅读；深墨色保证信息清楚；朱砂橙只标识主操作、当前位置与需要关注的引用。界面应克制、稳定、像一张可以工作的纸，不用大面积渐变或持续动效抢文稿的注意力。

**层级。** 文稿正文 > 当前任务和选中状态 > 导航与工具 > 辅助说明。颜色承担语义；不能只靠颜色传达类型、错误或保存状态。

### 2.3 间距、圆角、阴影与图标

- **现行尺寸。** 侧栏 268px；桌面顶栏 42px、浏览器顶栏 56px；格式栏 49px；状态栏 26px；窄屏格式栏 47px。页签最小 116px、最大 220px，选中页签上圆角 10px，并保留两侧外扩弧。
- **V1 约定的间距序列。** 新组件从 `4 / 8 / 12 / 16 / 20 / 24 / 32px` 选间距。现有紧凑控件可用 2、3、6px 微调；避免每个新原型自造一套比例。该序列目前是设计约定，尚未全部抽成 CSS token。
- **现行圆角。** 小控件 6px，中型容器 8px；格式按钮常用 7px；页签上缘 10px。阴影优先使用 `--ui-shadow-soft` 和 `--ui-shadow-raised`，低层级页面区域主要靠底色与细线分割。
- **现行图标。** 常规图标占位 17px，工具栏多用 18px；观译功能图标以 16×16 viewBox、圆角端点的墨色线条和少量朱砂结构构成。图标颜色继承 `currentColor`，关键动作可用强调线；不要使用系统 emoji 代替产品图标。纯图标按钮需要可见的悬停/焦点与可访问名称。PDF 工具栏的智能研读入口仅显示图标，保留“智能研读”的 `title` 与 `aria-label`，用 `aria-expanded` / `aria-controls` 关联面板；面板内部功能页签继续显示文字。

### 2.4 功能图标强制准则

用户于 2026-11-16 明确要求：**所有新增功能图标必须按现有观译风格和规范设计，这是每次项目开发迭代的必检项。** 新增或修改的 Web、客户端和原型功能均适用。

- **先复用，再扩充。** 先查现有 `gicon-*` 与 SVG 资产；同一功能跨端使用一致图形。缺少对应语义时，沿用 16×16 网格、圆端圆角、墨色主体和少量朱砂语义，新增共享图标定义及语义说明，不使用 emoji、文本符号或风格不同的外部图标代替。
- **以实际组件为准。** 继承 `currentColor`、现有强调色变量与主题 token；描边、留白、视觉重量和显示尺寸与相邻现有图标一致。不得将历史原型的局部色值、尺寸或描边直接提升为全局规范。品牌标识继续复用现有竹简资产。
- **状态与可访问性完整。** 纯图标按钮提供 `title`、`aria-label` 和可见键盘焦点，按钮内装饰 SVG 使用 `aria-hidden="true"`、`focusable="false"`；选中、展开、禁用等有正确语义。实色按钮使用高对比前景，功能图形对背景至少 3:1，状态切换不改变尺寸或位置。
- **随功能一起验收。** 补充可视手册样例，在实际使用尺寸下与现有图标并排检查，覆盖明暗主题及适用的常态、悬停、按下、选中、禁用、加载和焦点状态。记录引用资产或 Symbol ID、检查结果与截图；未满足时不得通过界面验收，见[验收矩阵 VW-12](../发布前体验走查清单与矩阵验收.md)。

### 3.1 宽屏工作区

```text

└────────────────── 状态栏 ────────────────────────────┘
```

- **现行。** 常驻主页页签与文档页签独立，不占一个真实文档 ID，关闭所有文档后仍可返回。页签可横向滚动。macOS 桌面版把交通灯安全区留在品牌区内，顶栏可拖动，交互控件明确设为不可拖动区域。新原型不得在这一安全区塞按钮。
- **现行。** 主页显示 268px 文档夹栏，右侧按独立搜索、AI 快捷对话、最近打开文档组织；搜索输入 34px 高、最大 340px 宽，不加“主页”标题或整行背景框，不放宣传性首屏。
- **Web 对话修订（2026-11-16）。** 进入 AI 对话后，同一左侧栏切换为“新对话”和会话列表，不再显示文件树。点击主页页签恢复主页文件列表；打开文档仍进入原有独立阅读/编辑工作区。会话列表展示未删除的对话，当前项有文字与选中状态，新对话留在对话空态。顶部保留“AI 对话”入口，从文档阅读或编辑返回时恢复当前会话、已有消息与未发送草稿，不新建空会话。窄屏由对话页头按钮打开覆盖会话栏，选择会话后收起，关闭支持 X、遮罩与 Esc，焦点归还。
- **Web 消息与输入（2026-11-16）。** 参考 ChatGPT 的阅读层级：消息净阅读宽度上限 760px、居中；用户消息右对齐、浅底圆角气泡，助手回答直接排版，取消“你的问题 / AI 对话”等重复可见角色标题。来源只在选中来源时显示于输入框下沿，已完成回答的证据按需展开；保留原文定位、异常、生成状态、复制与 Markdown 整理。页头为 54px 轻量结构，历史选择移入侧栏。主页与对话共用 24px 圆角输入面，单行起步、随内容增高，最大 min(200px, 26dvh) 后输入区滚动；“+”来源与发送/停止图标在框内，同一位置切换发送/停止。字体与色彩沿用观译 token。

### 3.2 窄屏与内容格式

- **现行断点。** `max-width: 760px`：主页文档夹栏默认收起，由文档夹按钮打开不超过 300px / 85vw 的覆盖抽屉并提供遮罩；阅读和编辑不显示该文件夹列表。格式栏横向滚动；分栏视图上下堆叠，拖动分隔器隐藏；弹窗贴近底部并保留可滚动内容。`max-width: 360px` 进一步压缩页签和设置表单。
- **现行容器断点。** Markdown 大纲依据预览容器宽度独立适配，任意窗口宽度下均适用：预览宽 >560px 内联 220px，宽 ≤560px 切 min(240px, 85%) 覆盖式，遮罩仅预览区，定位标题后自动收起；不覆盖源码或全工作区。
- **V1 约定。** 不因为控件太多就挤压正文到不可读；优先让工具栏滚动、抽屉覆盖或让辅助操作进入菜单。重要按钮保留文字或 `aria-label`，所有菜单在窄屏能完整看见。
- **现行。** Markdown 显示完整格式工具栏；TXT 保留纯文本/阅读相关操作；PDF 和 EPUB 在同一外壳内使用各自阅读工具栏。原型必须明确所演示的文件类型，不能把 Markdown 写作控件放在 PDF/EPUB 阅读器上。

## 5. 交互与内容要求

### 5.1 文件与编辑

- 新建、打开、保存、另存、移动、导出是不同动作，菜单和文案要写明结果与目标位置。未保存修改在页签和关闭流程中显式提示；磁盘版本冲突提供“查看版本 / 保留当前编辑 / 重新载入”的可辨选择。
- 源码、预览、分栏是同一份文档的不同操作视图；改变布局不能替换或隐藏未保存内容。分隔器可用键盘访问，方向与当前比例有说明。
- 文件格式是一级上下文：文档树、页签类型图标、工具栏、状态栏说同一种格式。图片、批注和导出失败给出恢复路径。
- MD/TXT 默认沿用 1.0.40 的编辑方式，直接显示完整工具栏、源码/预览/分栏、保存导出、主题和原智能审阅入口；TXT 不适用的 Markdown 格式项禁用。主动选择“阅读”才进入只读，普通文字输入、任务框、粘贴和格式快捷键都遵循同一个编辑状态；返回编辑保留三视图与正文。PDF/EPUB 使用各自阅读工具。主页的最近使用时间记录实际打开，不由保存、扫描或后台索引代替。

### 5.2 搜索、审阅与反馈

- 搜索要写清当前范围；命中高亮、当前命中、原文证据、空态分别可辨。原文与 AI 生成的关联说明在视觉和文案上分开。
- 批注锚点与文稿位置互相可定位；审阅侧栏的“仅本地”、同步中、失败或冲突状态要用文字说明。AI 功能保持主动触发，发送内容前说明范围。
- 反馈文案描述结果与下一步，例如“已保存到本地文档”“磁盘版本已更新，可查看版本”；避免只写“成功”“失败”或只变换颜色。
- 模型配置统一置于“顶部 … > 模型配置”，主页、MD 审阅和 PDF 研读不保留独立配置按钮；缺模型时输入和来源范围保留，错误文字说明配置路径，主动生成缺配置时通过全局菜单引导。模型配置弹窗不因所处工作区不同而复制。
- 主页默认自由对话，可选文档后基于相关片段回答；PDF 导读以“研读全文”处理所有页面的可提取文字与整页图像，逐块、逐页分批阅读并综合，不采样或截断原文快照；文档对话默认全文，可主动选择当前页、选区或指定页段，翻页不改变已选范围。发送前显示实际范围与提取不足，未经用户发送不调用模型。文档中的指令视为原文数据。
- PDF 全文研读先呈现文类、标题和概要，再展示核心方法、结果；研究过程与细节、术语概念、逐字摘引及译文、延伸理解按需展开。内容标明“原文事实 / 作者观点 / 辅助解释”，原文快照与解释分开显示，每项提供页码定位、完整摘录预览及“返回阅读位置”。扫描页与图表按整页图像送入支持图像输入的模型；覆盖信息分别列出文字块及图像已发送数，无文字层页标明按图像研读。图像来源仅注明页面与图表依据，不伪造可复制引文；点击“查看原图”才在本地生成原页预览，提供“定位图表所在页”和返回阅读位置。
- 图像研读使用独立的原页画布，白底 JPEG，最长边不超过 2000px、每页不超过 2MiB；不改变阅读缩放、位置、批注或 PDF 二进制。任一页渲染失败、图片不可传或模型不支持图像时，本次任务失败并保留旧结果，不静默跳页。页面图像和 base64 不进入研读记录及 Markdown，只保存本地来源身份与页码；预览按需渲染，关闭即清理。文字复制权限同时约束图像发送。选区解释、制卡和提问会发送选中文字及其所在整页图像，发送前在输入区或选区浮条披露；指定页段只发送该页段。
- 全文结果缓存包含来源版本与研读引擎版本；“重新研读”只有完整成功并保存后才替换同一键的旧结果，失败、取消与旧文件版本仍保留可读结果。摘要、分节、术语、摘引和延伸理解中的来源均保存完整快照，并可整理为 Markdown。一次全文研读的多批请求冻结同一连接和模型；关闭面板或切换文档取消在途任务，晚到结果不得覆盖。
- 导读和学习卡注明 AI 辅助，学习卡候选须预览、编辑、确认后才入自测与导出；自测先回忆再揭晓答案，使用用户自评。研读笔记与 PDF 原生批注分开保存，Markdown 整理不替代另存含原生批注的 PDF。
- 引用来自本地提取的证据，保留原文、文件页码、来源版本和定位；未知引用不可采用。旧版本可看快照、可导出，但不能假定位到新文件。图像依据不编造逐字引文、图表数字或精确框选区域；回跳诚实定位到原页。
- **EPUB 契约（1.0.44）。** 批注页复用原生高亮、颜色、笔记、CFI、删除及 Markdown 笔记导出；原书字节不变，注释不迁移成 `.REVIEW.md`。AI 辅助阅读仅发送当前章或选区的真实原文及临时证据编号，发送时冻结范围；章节使用原始 spine 索引。逐字匹配的引用才是原文依据；来源哈希、章节和精确文本由本地核验并转成定位 CFI，不接受模型自行提供的 CFI/URL/路径。无法精确匹配时定位章节并明确说明，不伪造命中。跨书首次定位须等待目标阅读器就绪并再次核验文档/来源，避免将加载中状态误判为来源变化。问作品保留既有范围与来源校验。
- **取消与持久化。** EPUB 关闭审阅、切换文档、回主页或销毁时取消在途生成，晚到结果必须同时通过文档、来源版本与请求身份校验；不会覆盖另一本文档。未发送问题、已有结果和原生注释保留；取消旧请求不得用旧问题覆盖生成期间新输入的下一条问题，关闭重开与重载保留最新草稿。AI 与原生注释分别持久化；保存失败保留活跃实例与草稿，不伪报成功。共享界面不能演变为共享各文档内容。
- **模型地址与反馈。** 裸域统一补全 `/v1/chat/completions`；已有兼容前缀和完整 Chat Completions 路径保留，不把 `/messages` / `/responses` 静默转换为另一协议。连接测试与实际生成共用端点/响应校验并实际请求配置服务。HTML 网页、非法/空 JSON、鉴权、额度、限流、模型不存在、网络和超时给中文原因与恢复操作，不显示密钥、响应正文或原生 JSON 解析异常；失败及取消保留输入和旧结果。唯一常驻配置入口仍是“顶部 … > 模型配置”。

### 5.2.1 会话管理与历史记录（2026-11-16 Web 修订）

- 顶部“AI 对话”是稳定的返回入口。从文档阅读或编辑返回时继续原活动会话，恢复已有消息和未发送草稿；只有主动“新对话”才创建新的会话。
- 会话行的“…”按钮与右键菜单提供同一“删除对话”动作。删除采用软删除：会话从侧栏移除，消息、来源和草稿仍保留，可在历史记录恢复，不提供永久删除。
- 全局“顶部 … > 历史对话记录”在主页、对话和文档工作区均可打开。“全部 / 已删除”用于筛选，列表显示标题、问题预览、时间与已删除标记；详情按只读消息流呈现，已删除记录显示删除时间与恢复入口。恢复后的会话重新进入侧栏，可继续对话。
- 查看与关闭历史记录不改变底层文档、活动会话或未发送草稿。右上角 X 与 Esc 关闭后归还触发入口焦点；只有用户主动“继续对话”才切换到对应会话。长历史只在弹框层滚动，标题、关闭和详情底部动作保持可达；桌面、窄屏、明暗主题需分别验收。

### 5.3 无障碍与动效

- 可键盘到达的控件必须有可见焦点。纯图标按钮提供 `aria-label`；选中、展开、错误状态使用恰当的 `aria-selected`、`aria-expanded`、`role="status"` 等，不靠颜色单独表达。
- **关闭规则（2026-11-16）。** 所有可关闭的应用弹框，包括选择来源、裁剪图片、保存修改确认、表格选择及 PDF 页段、学习卡、Markdown 整理，都在右上角提供 X 图标按钮。X 执行既有取消/关闭语义，不隐式提交、丢弃原文或执行破坏性动作；既有 Esc、遮罩和焦点归还继续按弹框契约保留。
- 动效只用于帮助定位和状态过渡，悬停/弹出保持短促；尊重 `prefers-reduced-motion`。长文阅读区不使用循环动画。
- **V1 验收目标：** 普通正文及按钮文字对背景至少 4.5:1、较大文字至少 3:1，明暗主题均检查。当前主按钮白字对 `#df4b25` 约 4.06:1，hover 对 `#ed5a2f` 约 3.44:1，尚未满足普通文字目标；后续改按钮颜色/字重时须一并解决，不能在原型里声称已通过。新增 PDF 研读主按钮采用较深的 `--ui-color-public-pressed`，验收仍须覆盖默认、悬停、禁用与焦点状态。

### 5.4 模型连接与运行环境（2026-11-15 开发调整）

- 连接配置与当前模型分开保存。手动接入仅需服务地址和 API Key；模型列表支持勾选多个，单个模型同样可用。模型 ID 允许手动添加，并在输入旁说明使用服务提供的准确标识；列表获取失败不清除已有选项，也不阻止先保存连接。
- “顶部 … > 模型配置”保持唯一常驻设置入口。“顶部 … > 切换模型”打开二级菜单，各条目以 `role="menuitemradio"` 与 `aria-checked` 表示当前选择；跟随模式分别列出 Codex 与 Claude，手动模式列出已启用模型，顶栏不再常驻模型下拉。主页对话、MD/TXT 阅读与问作品、PDF/EPUB 研读使用同一当前模型；已开始的一次生成冻结连接与模型，切换用于下一次请求。
- 设置弹窗在 Web 和桌面均显示 CC Switch 跟随入口。本机增强版和桌面分别读取 Codex 与 Claude 当前配置，二级菜单列出两者；用户选择的来源以 `sourceApp` 持久化，跟随时不在本应用复制保存密钥。每次主动发送重新读取所选来源；双方同时可用时仍按用户选择，不自动改选；选中来源失效须提示并停止请求，不回退另一来源或旧连接，保留输入和已有结果。
- 直接打开文件的离线页保留原有工作区。需要 CC Switch 时展示本地增强版启动方法与明确链接，由用户主动打开，不自动重定向。`file://` 与本地增强版是不同的存储环境，界面必须说明原数据保留、文档和设置不会自动迁移。
- 弹窗标题与底部动作保持可见，长模型列表和说明在中部滚动。窄屏二级菜单限制在视口内，保留 `aria-label`、单选语义、Esc 与返回父菜单行为；深色主题沿用现有表面、文字与边线 token。连接测试、列表读取、未添加模型和运行时错误分别提供可操作反馈，不把“列表接口不可用”简单表述为“密钥无效”。

## 7. 后续原型和更新的交付约定

**研读进度与历史结果（2026-11-17）。** 当前任务的全文范围和分批进度独立显示。旧版采样、旧引擎或旧文件结果收进默认折叠的“查看此前的研读结果”，原范围说明与引用留在历史内部；重新研读期间上次完整结果也暂时折叠，不把旧覆盖数当作本次进度。展开状态在进度刷新时保持，失败或取消保留历史；只有新结果完成并保存后才展示当前全文结果。更晚的成功不得继续显示较早的失败提示。
