# 观译主页 × PDF 智能研读原型

## 目标场景

这是一个面向本地优先阅读与写作的概念验证原型：用户启动观译后先进入常驻主页，在同一工作台中完成四件事：从左侧文档夹继续打开资料、按最近打开时间找到文档、从 AI 快捷对话开始阅读任务、创建或整理 Markdown 笔记。打开 PDF、Markdown、TXT 或 EPUB 后进入独立阅读视图，隐藏主页的文档夹列表；顶部常驻“主页”页签用于返回文件管理。PDF 使用 HTML 模拟页面演示阅读与智能研读；Markdown 阅读时可点“编辑”进入编辑器；EPUB 显示明确标注的固定示例正文。真实 PDF/EPUB 文件内容和分页均未接入。

主页的最近文档按最近打开时间从近到远降序排列。产品契约为使用 `lastOpenedAt`，不以编辑保存时间替代打开时间；当前原型的新建、保存和页签切换仍使用演示时间，正式接入时需校准这些更新规则。AI 默认允许自由对话；选择文档后，回答会显示来源范围，并提供“进入智能研读”和“整理为 Markdown”两条后续路径。

## 独立阅读视图提案

这次按用户要求增加“打开文档后不显示文件夹列表”的原型方案，仅修改原型，没有改动正式应用。

- 首页保留文档夹、最近文档和 AI 快捷入口；打开文档后，外层文档夹栏退出阅读工作区，主文稿获得完整可用宽度。
- PDF 左侧只提供当前文档的“目录 / 书签”，可以收起；目录项用于跳页，书签按文档分别保存在当前浏览器。这里的书签不是磁盘 PDF 中的真实书签写入。
- 普通打开 PDF 默认进入纯阅读，右侧 AI 面板收起；点击“智能研读”后再展开。由 AI 对话的“进入智能研读”入口可直接进入研读状态。
- 窗口宽度为 760px 及以下时，文档目录改为覆盖正文的抽屉；1179px 及以下时，智能研读改为抽屉。窄屏目录和 AI 面板互斥，点击遮罩可以关闭当前抽屉。
- Markdown 先以阅读视图展示，点击“编辑”进入源码、预览或分栏编辑；TXT 保持纯文本阅读。

## 设计依据

- 产品基线：观译阅读器 1.0.40。设计依据：观译阅读器设计系统 V1.0（`docs/design-system/README.md`）。沿用 `--ui-*` 语义色、268px 侧栏、42px 顶栏、49px 工具栏、26px 状态栏、360px 智能研读抽屉和 760px 窄屏断点。
- 用户提供的 WPS 与墨刀首页截图，以及 WPS PDF 阅读视图：保留主页的左侧文件导航和最近列表；文档打开后隐藏文件夹列表，以当前文档目录/书签和正文为主，智能研读可主动展开。
- 主页快速入口“体验智能研读”直接打开示例 PDF 并展开导读面板。阅读视图复用 `docs/pdf-study/current.html` 的共享样式与交互，并增加当前文档目录/书签及主页消息桥接；不是独立复制一套研读原型。
- 业内公开产品的共同取舍：Zotero 以 Library/文献列表为中心，Readwise Reader 以阅读队列和 Library 为中心，Notion/Obsidian 以工作区或文件树为中心；它们普遍没有把“通用 AI 问答 + 文件列表 + 长文研读证据”放在同一个首屏。观译的差异点是把 AI 入口放在文档列表上方，同时把回答明确导向原文证据与 Markdown 笔记。

## 交互与状态覆盖

- 默认：主页页签常驻；主页文档夹、AI 快捷输入、快速开始、最近文档均可点击。文档打开后隐藏外层文件夹，PDF 默认收起 AI 面板。
- 选中/展开：当前页签、当前文档、文档来源、格式筛选和 Markdown 源码/预览/分栏视图均有选中状态；窄屏侧栏改为抽屉。
- 键盘焦点：按钮、页签、筛选、搜索框、对话框和编辑区均使用原生可聚焦控件；顶部搜索栏可即时筛选最近文档，`⌘/Ctrl + K` 聚焦搜索栏，回车打开首个匹配项，`Esc` 清空并退出。
- 禁用：AI 发送按钮在输入为空时禁用；对话提交保留原问题，避免空提交。
- 加载与错误演示：底部“预览状态”可切换首次使用、文件失效、AI 请求失败、未配置模型；当前以提示文案演示恢复路径。
- 空态：最近文档无结果时给出搜索和从左侧打开的下一步；首次使用状态引导新建 Markdown 或打开文档。
- 明暗主题：右上角切换，PDF iframe 会沿用工作台中的阅读主题。

## 与当前产品的差异

当前正式产品启动后直接进入文档工作区，最近文档只在搜索弹窗的空查询中出现；本原型增加固定“主页”页签、首页最近文档、AI 快捷对话、独立阅读视图和 Markdown 整理路径。PDF 智能研读仍是 HTML 模拟页面的嵌入式方案，AI 回答使用预设内容，尚未连接真实模型、文件索引、PDF 文本块/页码坐标证据层或正式首页路由。真实 PDF、EPUB 和模型能力需要另行实现与验收。

## 运行与验收

在项目根目录启动静态服务后打开 `docs/prototypes/home-study/index.html`。建议验收以下路径：

1. 首页加载后检查最近文档按时间降序；使用有边框的搜索栏即时筛选，回车打开首个匹配项；切换 PDF/Markdown/TXT/EPUB 筛选。
2. 选择文档来源，发送问题，检查来源范围、继续追问、整理为 Markdown、进入智能研读。
3. 新建 Markdown，切换源码/预览/分栏，保存后回到主页检查最近列表；刷新页面检查页签、主题和自建文档仍在。
4. 打开 PDF，确认外层文件夹消失、AI 默认收起、文档目录可收起和跳页；添加书签后切换文档并刷新，检查书签按文档保存。点击顶部“主页”页签，确认文件管理恢复。
5. 打开 Markdown，检查阅读视图到编辑器的切换；打开 TXT，确认没有 Markdown 格式操作。
6. 切换明暗主题和 1179px / 760px 两个断点，确认研读与目录抽屉、互斥行为、遮罩和底部弹窗可用。
7. 切换四种预览状态，确认空态、失效、模型失败和未配置模型都有可理解的下一步。

原型数据和书签保存在当前浏览器的 `localStorage`，不是正式文档数据库。进入产品实现前，需要补首页路由、真实 `lastOpenedAt` 索引及更新契约、文件失效/权限状态、AI 请求与取消/重试、Markdown 文档与磁盘更新，以及 PDF/EPUB 的证据链路。
