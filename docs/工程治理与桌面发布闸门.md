# 观绎 MD 工程治理与桌面发布闸门

## 1. 发布基线

- `v1.0.33` 固定指向已经发布的 1.0.33 源码，不随后续开发移动。
- 版本升级、源码变更和安装包必须对应同一提交；未升级版本时不得重新生成正式安装包。
- 每次发布从干净的 Git 提交开始，构建产物不纳入版本库。

## 2. 单一源码

- `css/app.css` 和 `js/app.js` 是可维护源码，`index.html` 是桌面端和离线 Web 共用的单文件产物。
- 修改拆分源码后必须运行 `node tools/sync-single-file.mjs`，不得只修改内联后的 `index.html`。
- 禁止在文件末尾追加覆盖规则修复布局；应修改所属组件的权威规则或共享布局令牌。

## 3. 布局契约

- 侧边栏宽度、顶栏高度、格式栏高度和状态栏高度由 `--guanyi-*` 令牌统一定义。
- 智能审阅抽屉与遮罩的顶部固定为顶栏与格式栏高度之和，底部固定在状态栏之上。
- macOS 只覆盖顶栏高度和标题栏安全区，不单独维护抽屉像素偏移。
- 品牌区右边界与侧边栏右边界一致；文档页签从该边界开始横向排列，新建按钮跟随末页签。

## 4. 构建前置

`npm run build:mac`、`npm run build:win` 和 `npm run build:desktop` 必须依次完成：

1. 同步拆分源码到 `index.html`。
2. 校验单文件与拆分源码逐字一致。
3. 校验布局令牌、唯一权威规则和构建顺序。
4. 在真实 Electron 渲染器中检查标准与窄窗口、明暗主题、多页签和智能审阅抽屉，并生成截图。
5. 以上通过后，才允许获取运行时、生成图标和调用桌面打包器。

## 5. 提交边界

- `.workbuddy/`、`.tmp-test/`、`release/`、缓存和本机状态不得提交。
- 工程治理与产品功能分开提交，便于定位回归和选择性回退。
- 打包前运行 `npm run test:regression:all`；失败时停止发布，不通过后置覆盖规避测试。
