# PDF 智能研读 · 设计系统 V1.0 刷新版

2026-11-13。供产品与交互评审，不包含正式应用功能或新安装包。当前评审入口为 `current.html`，功能范围仍是 v0.3，界面依据“观译阅读器设计系统 V1.0”刷新。

智能研读面向所有学科与专业，统一提供“导读、文档对话、学习卡、批注”。当前运动健康教材与论文只是两份虚构演示文件。顶部页签用于切换这些文件；无需先选专业，也不再分“教材学习 / 论文研读”两个模式 Tab。

AI 文档对话保留为核心入口，解释选区与自由追问在同一线程中继续。学习卡增加“为本文整理”的自动候选：正式设计在用户启动的研读准备完成后，按内容整理少量概念知识、核心论点/研究思路、方法、结论与边界等候选，无需逐段手选。用户预览、编辑并确认保留后，才进入“我的学习卡”、自测和导出。选区或回答的手动补充入口继续提供。

面板已去掉“通用研读 · 导读随本文结构适配”说明行及其图标。本版原型的候选是静态预设内容，仅展示准备完成后的效果，没有实际调用 AI 生成。

- [PRD](PRD.md)：场景、M1 范围、交互契约、来源数据、选型、分期和验收标准。
- [PaperQA2 预研究](PAPER_QA_预研究.md)：官方接口、观译接入方式、默认外联与小样本验证次序；尚未执行模型问答。
- [当前可点击原型](current.html)：设计系统 V1.0 刷新版，离线可运行。
- [历史 v0.3 原型](index.html)：保留刷新前的评审记录，不再作为当前视觉基线。
- `reader.html`：未完成的 v0.4 阅读档位探索稿，本轮不纳入评审或验收。
- [新版教材导读预览](preview-v1-textbook-light.png)、[新版论文研读预览](preview-v1-paper-light.png)、[新版深色问答预览](preview-v1-paper-dark.png)。

## 打开

可以直接在浏览器打开本目录的 `current.html`，保持同目录 CSS/JS 文件完整。也可以在项目根目录执行：

```bash
node docs/pdf-study/serve.mjs
```

随后访问 <http://127.0.0.1:9938>。服务只监听本机，仅提供本评审包的固定文件，不包含模型代理。按 Ctrl+C 停止。

## 设计系统刷新

目标场景：在 PDF 原文旁完成导读、可核验问答、学习卡和批注，不离开当前阅读上下文。

设计依据：`docs/design-system/` 的“观译阅读器设计系统 V1.0”，语义颜色与结构尺寸来自正式产品 `css/app.css`。本原型通过 `design-system-v1.css` 复制正式 `--ui-*` / `--guanyi-*` token 并为旧交互样式建立兼容别名，避免把正式应用中无关的编辑器规则加载到独立评审页。

本轮收敛内容：

- 品牌区与文档侧栏统一为 268px，PDF 工具栏 49px，图标按钮 32px，智能研读面板 360px，状态栏 26px。
- 文档页签改用正式 37px 桌面页签、PDF 图形类型块和与纸面相接的外扩弧；补齐 tablist、选中态和方向键切换。
- 主命令与面板页签恢复 12–14px 基线，补齐按下态、正式焦点环和明暗主题语义 token。
- 低于 1180px 时研读面板在 PDF 工具栏下方以遮罩抽屉覆盖，不改变阅读列宽；760px 以下文档页签完整保留并横向滚动，目录也改为覆盖抽屉；360px 为极窄基线。
- 纯图标命令保留稳定可访问名称，主题、目录和研读入口同步 `aria-pressed` / `aria-expanded`，关闭抽屉后焦点回到入口。

与正式产品的差异：顶部深色说明条只属于评审环境；PDF 页面仍由 HTML 模拟，问答与学习卡内容仍是本地预设，未接入真实 PDF.js、索引或模型；设计系统刷新不代表这些正式能力已经实现。

## 建议体验顺序

1. 打开教材示例文件，直接查看导读中的章节目标、问题与概念。点击问题只是准备草稿，确认后发送；无需选择文档模式。
2. 在正文点击一段或拖选文字，点击浮条“解释这段”。结果进入“文档对话”，显示冻结的选区范围和页码证据，可继续追问。
3. 翻到其他页后点击回答中的“第 42 页”，核对强调的原文，再点击“返回阅读位置”。
4. 直接打开“学习卡”，查看“为本文整理”的候选，不需要先选文字或提问。候选注明类型、原文和页码；预览后可以取消或编辑，确认保留才加入“我的学习卡”。选区或回答仍可“生成学习卡”作为补充。已保存卡片可开始自测，先回忆、再显示答案并自评。
5. 导出 Markdown，检查问题、答案、全部来源、逐字原文与复习状态。刷新页面后，已保存卡片、批注和页码仍在。
6. 通过顶部文档页签切到论文示例，仍使用同一个智能研读面板。导读按该文内容展示研究卡。问“这篇论文的结果可以直接用于老年人吗？”：当前页证据不足时扩大到“本文”后再发送，可看到第 3、7 页的支持原文。
7. 在“批注”输入自己的问题，切面板或翻页后再回来，草稿和开始输入时的来源保持关联。
8. 底部“预览状态”体验索引构建、扫描件、证据不足、请求失败、原文件更新；失败可重试，生成可取消。
9. 切换深色主题、收起目录或研读面板。窄屏面板位于 PDF 工具栏下方，保留翻页和收起入口。

教材完整示例页为 42、55、56、64；论文为 1、3、5、7。其他页显示占位说明，不伪装完整书籍。

## 原型与正式能力的差别

| 项目 | 本原型可体验 | 正式开发仍需完成 |
| --- | --- | --- |
| 阅读画布 | HTML 模拟原版页面、页码、比例、选区 | 真实 PDF.js 文字/坐标桥接与旋转映射 |
| 导读/问答 | 原创虚构资料、预设回答、范围与异常流程 | 本地解析、索引、真实模型请求、证据支持度验证 |
| 入口与导读 | 统一的四个功能页签；两份示例按内容展示不同导读 | 跨学科内容识别、通用降级与后续可调导读模板；不要求先选专业或文类 |
| 来源回跳 | 在编排的示例页中强调段落，并返回页码/滚动/引用焦点 | 真正 PDF 坐标定位、印刷页码、文件版本检测 |
| 学习卡 | 静态预设的文档候选、类型与页码、预览编辑、取消/确认保留；选区/回答补充、去重、自测和导出 | 研读准备完成后的真实 AI 候选整理、版本缓存、标签、撤销删除和完整恢复；按章批量/定时整理属于后续能力 |
| 保存 | 浏览器独立 localStorage；卡片/批注/位置/主题持久化，问答与草稿只在本次会话保留 | 生产级事务保存、跨版本迁移、持久问答和中断恢复 |
| 失败与解析 | 手动切换预览状态，演示取消/重试 | 真实服务/解析失败、部分页续传与覆盖范围校验 |
| OCR/表图 | 展示未支持状态；原创静态示意图 | OCR、表格、图形、公式和多模态能力 |

所有文档、研究和数值均是演示资料，无真实论文对应。问答不会联网，也不会读取个人文件。导出数据明确保留演示标记。本原型只使用专用存储键 `guanyi.pdf-study.prototype.v1`，“重置演示”不触及观译正式应用的数据。

自动生成候选与自动保存是两件事。候选不会计入已保存数量，也不会进入复习和导出；重复打开或翻页不应重复调用模型。正式设计会按文档版本和处理范围复用结果，新版本候选独立，用户已保存卡片及修改继续保留。

当前演示验证的是通用操作流程，不代表已用理工、人文、社科、法律等专业资料验证过解释与提取质量。跨学科样本及门槛已列入 PRD，正式开发时需要分别验证。

PRD 中的性能与质量指标是后续开发的目标，不能由这份原型验收推导为正式产品已达标。

## 后台验收

```bash
node tools/run-electron-smoke.mjs docs/pdf-study/acceptance.cjs
```

仅打开隐藏 Electron 测试窗口，不加载正式应用主进程。使用 `.tmp-test/pdf-study-prototype/` 隔离资料；测试中拦截所有 HTTP/HTTPS 请求，截图输出至本目录，JSON 结果和下载文件在对应测试 run 目录。新版脚本在原业务流程之上增加设计 token、尺寸、断点、遮罩、ARIA 和焦点契约。

本机 Electron 依赖不可用时，可用 `acceptance-browser.cjs` 做当前页面的设计与视觉验收。脚本默认读取项目内 Playwright；外部运行时可通过 `GUANYI_PLAYWRIGHT_MODULE` 指向 Playwright 的 `index.js`，通过 `GUANYI_CHROMIUM_EXECUTABLE` 指向 Chromium。该路径覆盖真实交互和截图，但不替代 Electron 脚本中的全部历史业务回归。

实际覆盖及结果见 [验收记录](验收记录.md)。
