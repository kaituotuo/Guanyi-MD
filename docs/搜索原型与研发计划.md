# 观绎 MD 搜索原型与研发计划

## 1. 产品边界

搜索服务于“已经进入观绎 MD 的资料”，默认范围是内置文档、用户打开的单份文档，以及用户主动添加的目录。应用不会在未授权的情况下扫描整台电脑。

搜索只有一个用户入口，内部组合三种互补能力：

- **全文匹配检索**：匹配文件名、目录名、相对路径和 Markdown/TXT 正文，适合查找准确词句。
- **语义检索**：理解查询与段落含义之间的相关性，适合用户记得意思、但记不住原词的情况。该能力只在桌面版自动启用。
- **原文回答**：在前两类检索结果之上自动判断“原文直答”或“原文类答”，选择可定位、可逐字复现的原文证据回答作品内问题或提供文学类比；关联说明与原文引文分开展示，证据不足时不强行作答。

用户不需要选择搜索模式。产品先返回准确匹配，再自动补充相关内容，并在统一列表中去重排序。原文直答属于用户主动执行的回答动作，不会在输入过程中自动调用回答模型。

## 2. 交互原型

### 入口

- 位置：左侧栏“文档列表”标题之后、“添加目录”之前。
- 形态：搜索图标按钮，悬停提示“搜索文档”。
- 快捷键：`Ctrl/Cmd+Shift+F` 打开文库搜索；面板内 `Ctrl/Cmd+Enter` 生成原文回答。`Ctrl/Cmd+S` 继续用于保存，`Ctrl/Cmd+F` 继续用于当前文档查找。
- 目录更新：在“添加目录”后提供刷新图标，一次重新扫描全部已授权目录；新增、更新、缺失文件会立即反馈到文档树。

### 搜索面板

- 桌面端：宽 720 px、顶部居中的模态面板。
- 移动端：左右保留 10 px，面板贴近视口底部，结果区独立滚动。
- 空查询：展示最近打开的 10 份文档。
- 有查询：先显示文件名、目录和正文的准确匹配，桌面版随后自动补充本地相关结果。
- 结果结构：标题、路径、正文片段、命中字段；关键词以朱砂色底纹高亮。
- 键盘：上下方向键切换结果，Enter 打开，Esc 关闭。
- 打开结果：切换到对应文档，并在源码编辑器中选中、滚动到命中段落。
- 原文回答：全文与语义检索完成后，点击“原文回答”生成；作品内事实与人物关系显示“原文直答”，现实问题的文学映照显示“原文类答”。相关证据存在时自动联合多部作品，不要求用户选择模式。
- 答案操作：回答区展示原文、作品与章节，点击引文可打开文档并定位；支持收藏、复制带出处的 Markdown 引用，以及一键接续写入当前文档。未配置回答模型时按本地相关度列出原文证据。

### 状态反馈

- 搜索显示结果数量、空状态，以及“正在补充相关内容”或“已完成本地搜索”。
- 本地相关能力不可用或执行失败时，保留用户查询与已经得到的准确匹配结果。界面不显示技术堆栈或本机路径，但会区分模型缺失、搜索服务启动失败、索引未建立和目录需授权。

## 3. 技术架构

### 什么是高召回语义搜索底座

“高召回”先解决“不要漏掉可能相关的原文”，再解决“哪些应该排在前面”。它不是单次把问句转成向量并取最近的几段，而是一套可复用的检索基础设施：

- 同一份文档建立句子、段落、多段、小节、章节五种粒度，既能找精确句子，也能用长上下文补充语义。
- 原始问句、稳定词片、本地意图扩展和语义向量并行召回，兼顾原词、错字、同义改写与情节问句。
- 多路结果用加权 RRF 合并，再按语义分、原句匹配、片段覆盖、问句复述惩罚排序，最后进行同段去重和跨文档分散。
- 粗粒度结果必须回落到可定位句子，因此搜索结果和大模型引用都能回到原文位置核验。

与之前“一个问句 + 一次向量搜索 + Top K”的区别，不在于换一个更大模型，而在于扩大候选集、保留可核验锚点，然后稳定排序。普通搜索继续使用原有统一结果页；“问作品”只是在这套底座之上增加问题路由和证据编排，不改写原有搜索。

```mermaid
flowchart LR
  A[已接入的 Markdown/TXT 文档] --> B[句子/段落/小节/章节分层与指纹]
  B --> C[受限 Electron IPC]
  C --> D[bge-small-zh-v1.5 INT8 ONNX]
  D --> E[用户提供的 512 维向量]
  B --> F[Meilisearch 中文全文索引]
  E --> F
  F --> G[原始语义 / 扩展语义 / 中文片段多路召回]
  G --> H[加权 RRF 与统一特征排序]
  H --> N[父级上下文恢复 / 段落去重 / MMR]
  N --> I[精确句子证据]
  I --> O[搜索结果与点击定位]
  I --> J[原文证据编号与逐字校验]
  J --> K[可选回答模型只选择证据编号]
  K --> L[原文直答或跨作品原文类答]
  L --> M[收藏 / 复制引用 / 接续写入]
```

关键约束：

- Electron 保持 `contextIsolation: true`、`nodeIntegration: false` 和 `sandbox: true`。
- preload 只暴露受限文件、目录、状态、语义搜索和模型请求方法，不暴露 Node.js、文件系统或任意网络调用。
- 主进程只接受当前主窗口发出的语义搜索 IPC。
- 桌面版的云端回答模型请求也经过受限 IPC：只允许 `http/https`，限制 URL、API Key、请求体、响应体和超时，并支持按请求编号取消。Web 版按“本机转发 -> 浏览器直连”降级，不得到桌面文件或搜索进程权限。
- 模型禁止远程加载，并校验固定 revision 与 ONNX 文件 SHA-256。
- Meilisearch `v1.53.1` 作为桌面端随包 sidecar，只监听随机 `127.0.0.1` 端口，关闭遥测；端口和主密钥不暴露给渲染进程。
- 索引按文档内容指纹增量更新；删除文档后同时清理对应全文记录和向量。启动时校验实际记录数，发现中断或损坏会整体重建。
- Meilisearch 数据库、元数据和本地主密钥保存在 Electron `userData/search/`，不写入原始文档目录。

## 4. 当前实现

### M0：可交互原型（已完成）

- 搜索入口、720 px 模态面板、移动端布局与最近文档。
- 统一搜索、结果高亮、键盘导航、命中文本定位。

### M1：普通搜索（已完成）

- 文件名、目录名、相对路径和正文关键词匹配。
- 精确短语优先；中文查询同时评估稳定片段和字符覆盖，并保留最近访问轻量加权。
- 延迟加载目录文档，遵守 20 MB 单文件上限与目录读取授权。

### M2：本地分层混合搜索（已完成）

- `bge-small-zh-v1.5`、512 维归一化向量、CLS pooling。
- 使用 Meilisearch `userProvided` 向量与中文全文检索，同一请求自动融合准确词句和语义相关性，用户不选择搜索模式。
- 建立“句子 / 段落 / 多段 / 小节 / 章节”五级正式记录。只对句子执行模型推理；段落、多段、小节、章节使用所属句子的归一化质心向量，避免整篇无章节长文章或整本书被截断为一个向量。多段按相邻自然段自适应聚合，不跨越章节边界，每个多段命中后仍回落到句子证据。
- 纯文本标题识别同时支持“第 X 回/章/节”、中英文章节词、数字与小数层级、括号编号、序章/尾声等命名章节、Setext 下划线标题；完全无标记的短标题只在文档内出现重复的“独立短行 + 后续正文”结构时才作为章节，避免把列表项或普通短句误分章。
- 分层切分规则有独立版本号；标题兼容规则升级后，旧文档指纹会自动失效并逐份重建索引。
- 每句保留精确源码 `start/end`。粗粒度命中会在对应父级范围内二次检索最相关句子；语义结果没有字面词时强调证据句，不制造红色关键词。
- 检索逻辑不包含书名、人物或问句的业务硬编码；经典小说查询只是质量回归样本。任意后续添加的 Markdown/TXT 文档使用同一套层级解析、向量化和混合检索管线。
- 文档指纹驱动增量更新：新增文档建立索引，内容变化仅重建该文档，移除文档同时清理其记录。
- 渲染进程先读取后端保存的文档指纹，只对变化文档逐份切分并通过 IPC 传输；完成后再提交当前文档清单清理失效记录，避免大目录每次查询都发送全部分层文本。
- 未授权目录若已有索引则保留旧索引，并明确提示需要授权后更新；不会因为一次权限失效误删仍可使用的离线索引。
- 查询使用与 UI 返回数量无关的固定候选池，并行执行原始混合、纯语义句子、意图扩展句子、父级上下文和中文稳定片段召回；所有通道通过加权 RRF 融合，只在最后截取 36 项。同一文档中指向同一段原文且证据范围高度重叠的关键词、语义命中合并为一个条目，避免同一句占用多个展示位置。
- 中文错字容错不把整句当成唯一检索词，而是在查询时生成有上限的 2–6 字稳定片段，保留“不/未/无”等单字否定证据。片段覆盖率同时考虑最长共同子串、二元组和字符覆盖，不向索引写入额外 n-gram 记录。
- 句子向量是最终相关性主体；段落、多段、小节和章节向量仅用于补充召回与恢复上下文，不用算术平均后的父级分数覆盖具体证据句分数。
- 最终排序统一使用语义分数、RRF、原句匹配、中文片段覆盖、问句意图证据和查询复述惩罚。“搜索袭人名字来历应返回原文”之类测试文档不得排在姓氏、改名、诗句出处等原文证据之前。
- 同一句子锚点先合并，同一段落在前 10 名中最多出现一次；对高度相似摘录执行 MMR 式惩罚，避免一整屏都是同一段的重复句子。
- 每次复用搜索连接前先检查本地服务健康状态；sidecar 异常退出后，下一次同步或查询会自动重新启动并复用持久索引。
- 服务只在本机回环地址运行；文档、文本向量和查询均不上云，不依赖远程模型接口。

### M3：原文直答、原文类答与答案资产（已完成 Web 端）

- 保持全文匹配和语义检索流程不变，在统一结果之上增加原文回答。
- 对文库内事实、人物关系和作品主题问题生成同义检索表达并执行“原文直答”；对现实问题先抽取人物处境、行动、因果、资源、制度、冲突和情感等文学母题，再复用现有语义检索 API 执行“原文类答”。
- 候选证据优先让不同作品获得展示机会；类答在存在有效证据时优先选择 2 至 4 部作品形成互补回答，具体作品数量由证据决定，不增加搜索模式开关。
- 每条候选证据保存 `docId/start/end/hash`；展示前重新从当前文档读取并校验，引文不是由模型生成。
- 回答模型只能返回证据编号、排列顺序、置信度和“关联说明”，未知证据编号与模型返回的引文文本一律丢弃。
- 关联说明明确标记为 AI 内容；证据不足时显示“暂无足够原文”，不拼凑名著原文。
- 未配置回答模型或模型请求失败时，保留本地检索能力，并按相关度展示可定位的原文证据。
- 原文回答只在点击按钮或按 `Ctrl/Cmd+Enter` 后调用模型。若用户配置的是云端模型，仅发送本次候选引文而非整本文库；若配置本地 OpenAI 兼容模型，则可保持回答链路本地运行。
- 最终答案可收藏到现有应用状态中，随浏览器状态和 Electron 原生状态备份共同持久化；最多保留 50 条，每条最多 5 段引文，避免状态文件无限增长。
- 复制与接续写入统一输出带问题、AI 关联说明、逐字引文、作品名和章节的 Markdown。接续写入优先使用打开搜索前记录的源码光标；位置无法可靠确认时追加到文末，并通过现有编辑历史链路支持撤销。
- “问作品”不再从文档开头或简单段落匹配中取证，而是复用 M2 的同一本地高召回索引。原问题先查询可用旧索引，同时后台增量同步；规则路由或模型规划再生成最多 5 条检索表达，以最多 2 路并发执行并按原文锚点融合、跨作品分散。
- 问作品模型链路分为“问题规划”和“证据回答”两段。输入只包含规范化问题、最多 600 字当前上下文和总计不超过 12000 字的编号候选；回答模型只能选择现有证据编号，展示前按 `docId/start/end/hash` 再次核验逐字原文。
- 问题规划失败时回退到本地规则路由；本地语义服务失败时回退到关键词证据；模型超时、限流或网络错误最多重试一次，仍失败则只展示可定位原文。任一阶段失败都不会损坏索引、文档或已完成的其他阶段。

## 5. 后续研发计划

### M4：检索质量与大目录性能（容错与排序已实现，大规模基准持续进行）

- 已建立《红楼梦》《三国演义》《鲁迅全集》真实全文矩阵，覆盖“袭人的名字来历”、“不再沉默中爆发”错字查询、“沉默之中，不奋起便消亡”同义改写以及查询复述文档干扰。
- 已实现多路独立召回、加权 RRF、统一特征排序、段落去重和稳定性检查；只有该方案未达到金标时，才评估额外约 1.11 GB 的 `bge-reranker-base`，本版本不增加该体积。
- 已将索引改为后台防抖、逐文档增量同步；后续补充取消、暂停和剩余时间反馈。
- 对 100、500 份文档分别记录首次索引时长、增量索引时长、内存峰值和结果延迟。
- 增加索引管理：查看占用空间、手动重建、清除本地索引。

### M5：桌面发布

- 在 Apple Silicon macOS 与 Windows x64 上分别执行安装、升级、卸载和离线搜索验收。
- 完成 Apple Developer ID 签名与公证、Windows Authenticode 签名。
- 跟进 `@huggingface/transformers`、`onnxruntime-node` 与 `sharp` 安全更新；在上游无修复版本期间限制模型与图片处理输入面，并保留依赖审计记录。

### M6：可选扩展

- 仅在用户明确选择新的目录后扩大搜索范围，不提供默认全盘扫描。
- 支持按目录、文件类型、更新时间过滤结果。
- 评估索引加密；该项需要同时验证密钥存储、迁移与性能成本后再进入实现。

## 6. 验收标准

- 普通搜索可以分别命中文件名、目录名、Markdown/TXT 正文。
- 空查询展示最近文档；无结果、加载中、失败回退都有明确状态。
- 点击结果后打开正确文档，光标定位到正确段落。
- 语义搜索在断网状态可完成模型加载、索引和检索。
- 句子、段落、多段、小节和章节五种粒度都参与召回，且段落、多段、小节或章节命中会返回可定位的精确句子证据。完全无章节长文章也必须生成多个有界、有重叠的多段记录。
- 普通关键词和语义相关结果都能最小定位到句子；同一文档不同段落的相关句子可分别出现，同一段落不重复占位。
- “谁打了黄盖”可定位到《三国演义》中黄盖受刑的章节，“袭人的名字来历”可定位到《红楼梦》中“花气袭人知昼暖”的相关章节；结果中的“黄盖”“袭人”使用与关键词搜索相同的朱砂色高亮。
- “不在沉默中爆发”的原句第 1；错字查询“不再沉默中爆发”在前 3 名找到原句，并高亮“不”和“沉默中爆发”；“沉默之中，不奋起便消亡”在前 5 名找到原句。
- 同一查询连续执行 20 次，前 10 名顺序完全一致，同一段落最多一条；三部真实全文的热搜索 P95 不高于 2 秒。
- 对完整问题执行原文直答时，模型只能选择当前检索返回的证据编号；每条展示引文都必须能用保存的 `start/end/hash` 在当前文档中逐字复现。
- 点击原文直答中的任一引文，可以打开正确文档并定位、高亮对应原文；文档内容变化导致校验失败时不得继续展示旧引文。
- 回答模型返回未知证据编号、伪造引文、空结果或低置信拒答时，不得将其内容显示为原文。
- “刘关张情谊深厚”等作品内关系问题应显示“原文直答”；“为什么一个枢纽城市会衰落”等跨情境问题应显示“原文类答”，并在存在相关候选时允许联合多部作品。
- 收藏经重启和普通版本升级后仍存在；收藏对应的文档内容发生变化时，旧引文不得继续作为可核验证据展示。
- 复制结果包含作品与章节出处；接续写入产生一条可撤销的编辑历史，不覆盖当前选区或后续正文。
- 添加一份测试集中从未出现过的文档后，无需修改规则即可语义召回；修改后旧向量被替换，移除后不再出现旧结果。
- 修改一份文档时只重建该文档索引；移除文档时不再返回旧结果。
- 模型缺失或校验失败时不阻塞普通搜索。
- 390、768、1024、1440 px 宽度下，搜索面板不产生横向滚动、文字遮挡或不可点击控件。
