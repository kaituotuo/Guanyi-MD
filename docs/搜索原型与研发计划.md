# 观绎 MD 搜索原型与研发计划

## 1. 产品边界

搜索服务于“已经进入观绎 MD 的资料”，默认范围是内置文档、用户打开的单份文档，以及用户主动添加的目录。应用不会在未授权的情况下扫描整台电脑。

搜索只有一个用户入口，内部自动组合两种互补能力：

- **关键词**：匹配文件名、目录名、相对路径和 Markdown/TXT 正文，适合查找准确词句。
- **语义相关**：理解查询与段落含义之间的相关性，适合用户记得意思、但记不住原词的情况。该能力只在桌面版自动启用。

用户不需要选择搜索模式。产品先返回准确匹配，再自动补充相关内容，并在统一列表中去重排序。

## 2. 交互原型

### 入口

- 位置：左侧栏“文档列表”标题之后、“添加目录”之前。
- 形态：搜索图标按钮，悬停提示“搜索文档”。
- 快捷键：`Ctrl/Cmd+Shift+F`。

### 搜索面板

- 桌面端：宽 720 px、顶部居中的模态面板。
- 移动端：左右保留 10 px，面板贴近视口底部，结果区独立滚动。
- 空查询：展示最近打开的 10 份文档。
- 有查询：先显示文件名、目录和正文的准确匹配，桌面版随后自动补充本地相关结果。
- 结果结构：标题、路径、正文片段、命中字段；关键词以朱砂色底纹高亮。
- 键盘：上下方向键切换结果，Enter 打开，Esc 关闭。
- 打开结果：切换到对应文档，并在源码编辑器中选中、滚动到命中段落。

### 状态反馈

- 搜索显示结果数量、空状态，以及“正在补充相关内容”或“已完成本地搜索”。
- 本地相关能力不可用或执行失败时，保留用户查询与已经得到的准确匹配结果，不向用户暴露模型错误。

## 3. 技术架构

```mermaid
flowchart LR
  A[已接入的 Markdown/TXT 文档] --> B[渲染进程分片与指纹]
  B --> C{搜索方式}
  C -->|准确匹配| D[文件名/路径/正文匹配]
  C -->|自动补充相关内容| E[受限 Electron IPC]
  E --> F[bge-small-zh-v1.5 INT8 ONNX]
  F --> G[本地持久化向量索引]
  D --> H[统一结果列表]
  G --> H
  H --> I[打开文档并定位原文]
```

关键约束：

- Electron 保持 `contextIsolation: true`、`nodeIntegration: false` 和 `sandbox: true`。
- preload 只暴露状态、建索引、查询和进度四类语义搜索能力。
- 主进程只接受当前主窗口发出的语义搜索 IPC。
- 模型禁止远程加载，并校验固定 revision 与 ONNX 文件 SHA-256。
- 索引按文档内容指纹增量更新；删除文档后同时清理对应向量。
- 向量索引保存在 Electron `userData/search/`，不写入原始文档目录。

## 4. 当前实现

### M0：可交互原型（已完成）

- 搜索入口、720 px 模态面板、移动端布局与最近文档。
- 统一搜索、结果高亮、键盘导航、命中文本定位。

### M1：普通搜索（已完成）

- 文件名、目录名、相对路径和正文关键词匹配。
- 多关键词 AND 匹配、短语加权和最近访问轻量加权。
- 延迟加载目录文档，遵守 20 MB 单文件上限与目录读取授权。

### M2：本地语义搜索 MVP（已完成）

- `bge-small-zh-v1.5`、512 维归一化向量、CLS pooling。
- 建立“句子 / 段落 / 多段 / 小节 / 章节 / 整书”六级本地索引：基础文本块直接向量化，小节、章节和整书使用归一化质心向量聚合。
- 粗粒度命中会回落到得分最高的具体原文片段，搜索结果仍可直接定位和高亮；长段落使用重叠切分。
- 检索逻辑不包含书名、人物或问句的业务硬编码；经典小说查询只是质量回归样本。任意后续添加的 Markdown/TXT 文档使用同一套分片、向量化、多粒度聚合和混合排序管线。
- 文档指纹驱动增量更新：新增文档建立索引，内容变化仅重建该文档，移除文档同时清理其向量。
- 增量索引、索引持久化、统一排序与无感降级。
- 不启动 HTTP 服务，不上传文档，不依赖远程模型接口。

## 5. 后续研发计划

### M3：检索质量与大目录性能

- 优化准确匹配与相关内容补充的融合排序，并建立中文查询回归样本。
- 将索引任务调度到空闲时段，补充取消、暂停和剩余时间反馈。
- 对 100、500 份文档分别记录首次索引时长、增量索引时长、内存峰值和结果延迟。
- 增加索引管理：查看占用空间、手动重建、清除本地索引。

### M4：桌面发布

- 在 Apple Silicon macOS 与 Windows x64 上分别执行安装、升级、卸载和离线搜索验收。
- 完成 Apple Developer ID 签名与公证、Windows Authenticode 签名。
- 跟进 `@huggingface/transformers`、`onnxruntime-node` 与 `sharp` 安全更新；在上游无修复版本期间限制模型与图片处理输入面，并保留依赖审计记录。

### M5：可选扩展

- 仅在用户明确选择新的目录后扩大搜索范围，不提供默认全盘扫描。
- 支持按目录、文件类型、更新时间过滤结果。
- 评估索引加密；该项需要同时验证密钥存储、迁移与性能成本后再进入实现。

## 6. 验收标准

- 普通搜索可以分别命中文件名、目录名、Markdown/TXT 正文。
- 空查询展示最近文档；无结果、加载中、失败回退都有明确状态。
- 点击结果后打开正确文档，光标定位到正确段落。
- 语义搜索在断网状态可完成模型加载、索引和检索。
- 句子、段落、多段、小节、章节和整书六种粒度都参与召回，且章节或整书命中会返回可定位的原文证据。
- “谁打了黄盖”可定位到《三国演义》中黄盖受刑的章节，“袭人的名字来历”可定位到《红楼梦》中“花气袭人知昼暖”的相关章节；结果中的“黄盖”“袭人”使用与关键词搜索相同的朱砂色高亮。
- 添加一份测试集中从未出现过的文档后，无需修改规则即可语义召回；修改后旧向量被替换，移除后不再出现旧结果。
- 修改一份文档时只重建该文档索引；移除文档时不再返回旧结果。
- 模型缺失或校验失败时不阻塞普通搜索。
- 390、768、1024、1440 px 宽度下，搜索面板不产生横向滚动、文字遮挡或不可点击控件。
