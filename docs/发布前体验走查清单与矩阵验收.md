# 观绎 MD 发布前体验走查清单与矩阵验收

本文是每次正式打包前的固定验收基线，覆盖“创建、打开、组织、编辑、搜索、保存、导出、删除、恢复”的完整文档生命周期。验收原则是：同一功能不仅单独可用，还要在其他格式、图片、列表和视图前后穿插使用时保持结构、光标、撤销历史和最终 Markdown 一致。

## 1. 执行规则

- 测试对象：拆分源码、单文件 `index.html`、Apple Silicon 桌面应用三者必须同源。
- 视图范围：源码、预览、分栏；标记为“三视图”的案例必须在三个视图各执行一次。
- 数据范围：普通中文、英文、长段落、无标题长文、规范/不规范标题、TXT、Markdown、1 到 7 张图片。
- 失败处理：先定位共同根因，再扩展到同类边界并补回归用例，不对单一示例打补丁。
- 反馈锁定：每个用户体验问题都要进入“近期反馈锁定矩阵”，记录共同根因、自动化入口和人工复核项。
- 图标对比：实色按钮的功能图标不得与背景使用同色或近似色系；双色图标进入实色按钮时必须统一映射为白色或墨色等高对比前景色。常态、悬停、按下、禁用、加载及明暗主题逐态验收，功能图形与背景对比度不得低于 `3:1`，不得依靠整体透明度表达状态而牺牲可读性。
- 变更触发：修改某类功能时，必须运行该分组全部历史用例和 `test:editor-matrix`；新增功能必须先补案例再视为完成。
- 安全边界：删除目录或磁盘文件前先确认语义；“移除目录/本地文档”不得删除真实文件。
- 通过标准：无内容丢失、无孤儿列表项、无多余空行、无错误格式跳转；保存、重载、切换视图后结果一致。

状态标记：`A` 自动化通过，`B` 真实浏览器通过，`D` 桌面安装包验收，`M` 每次发布需人工复核。
