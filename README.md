# 观译阅读器

**Guanyi Reader · 俯仰观物，译述我心。**

观译阅读器是一款本地优先的文本阅读与批注工具，支持 Markdown、TXT、PDF 和 EPUB。用同一套文档列表与页签组织阅读，打开不同格式时自动切换顶部工具栏，保留统一的图标风格。

| 格式 | 阅读与编辑 | 保存与导出 |
| --- | --- | --- |
| Markdown | 源码、预览、分栏；常用格式、表格、任务列表、图片与批注 | 保存原文、另存、移动；导出 Markdown、PDF、PNG |
| TXT | 中文编码识别、长行换行、段落阅读与纯文本编辑 | 保存原文本与换行 |
| PDF | 官方 PDF.js 阅读器；当前页/总页数、比例缩放、键盘与按钮翻页、查找、高亮、文字笔记和评论 | 本地保留批注草稿，另存含原生批注的 PDF |
| EPUB | epub.js；章节、字号、阅读位置、键盘翻页、高亮、摘录与笔记；共享三页签智能审阅 | 标注保存在应用内，可导出 Markdown 阅读笔记 |

PDF / EPUB 首版编辑范围为高亮、批注和笔记。不提供 PDF 正文重排、OCR、EPUB 正文改写或 DRM 绕过。扫描 PDF 能否选中文字取决于文件是否已有文字层。

界面与后续原型统一参照 [观译阅读器设计系统 V1.0](docs/design-system/README.md)；色彩、组件与布局可在[可视组件手册](docs/design-system/index.html)中查看。该规范以当前前端为基线，通用样式源码位于 `css/app.css`，主页与 PDF 研读分别位于 `css/home-workspace.css`、`css/pdf-study.css`。

2026-11-16 Web 体验更新：主页与 AI 对话采用简洁消息布局和自适应输入框，对话左栏改为会话列表；模型切换位于“…”菜单的二级单选列表，可分别跟随 CC Switch 当前 Codex 与 Claude 连接；弹框关闭按钮与客户端品牌图标已统一。继续使用 `http://127.0.0.1:9929/`，刷新生效。详见 [Web 体验优化与验收记录](docs/Web体验优化-20261116.md)。

Web 版与 Mac 客户端使用同一份界面源码。双击「启动观译Web.command」可在本机使用 Web 版。Web 服务与 CC Switch 同步方式见 [Web 版对齐记录](docs/Web版对齐与CC-Switch.md)。

## 使用范围与数据

- 文本文件支持 `.md`、`.markdown`、`.txt`，单份不超过 20 MB；PDF 单份不超过 1024 MB，EPUB 单份不超过 100 MB。较大的 PDF 需要足够的可用内存与磁盘空间。
- 目录扫描默认最多 5 层，可收录 Markdown、TXT、PDF 和 EPUB；全库关键词和语义搜索仍面向 Markdown / TXT 正文。
- Markdown 支持图片、表格、任务列表、50 步撤销、批注伴随文件、明暗主题和多页签。
- 本地搜索使用随应用提供的 `bge-small-zh-v1.5` INT8 ONNX 模型与 Meilisearch；索引与查询运行在本机。
- AI 辅助阅读须主动触发，使用配置的服务提供商。生成辅助阅读可能发送当前 Markdown 全文；问作品会发送问题、上下文和选取的原文证据。请先确认内容适合发送给该服务。
- 新主页的自由对话发送问题与同模式对话历史；选择文档后，会发送问题、选定文档的相关原文片段及对应会话历史，并显示本次使用范围。当前每次最多选择 8 份文档，总原文上限 36,000 字符；主页来源读取 PDF 每份最多 30 页，不代表整份文件已读完。
- PDF 智能研读在用户准备导读、生成学习卡或发送文档问题时，才发送所选范围的原文、问题及该任务需要的上下文给配置的模型。打开文件、浏览主页和本地解析本身不调用模型；本地定位坐标不额外发送给模型。引用校验确认来源存在，不能替代用户核验 AI 解释。
- EPUB 智能审阅仅在主动生成或发送问题时处理当前章节、选中文字或用户选择范围内的本地原文证据；源哈希、章节索引和 CFI 留在本地映射，晚到结果、取消与原生注释保存按文档隔离。
- API Key 默认只在当前会话保存；选择“记住”后存入本地浏览器存储，并非 macOS Keychain。
- 对话、研读笔记和学习卡保存在本机应用资料中，建议定期整理为 Markdown；EPUB 笔记可导出 Markdown，PDF 原生批注通过“另存为”导出。PDF 另存不替代研读内容的 Markdown 导出。应用内缓存不是独立备份或跨设备同步服务。

[合规、隐私、安全与证书说明](docs/合规与安全说明.md)记录实际边界和第三方许可；[第三方资源目录](vendor/README.md)保留依赖来源与许可证。项目主代码目前未授予通用开源许可，第三方组件分别适用其自身许可证。

## 开发与构建

```bash
npm install
npm run desktop
```

Web 版与客户端共用主页、Markdown/TXT 编辑、PDF/EPUB 阅读与批注、智能审阅和 PDF 研读模块。双击项目根目录的 **“启动观译Web.command”**，或运行 `npm run web`，会启动本机服务并打开浏览器；默认地址为 `http://127.0.0.1:9929/`。已有本项目兼容服务会直接复用，端口被其他服务占用时使用空闲端口。也可运行 `node tools/dev-server.mjs --port 9929`。

在“顶部 … > 模型配置”中点击 **“使用 CC Switch 当前配置”** 即可直接跟随，不用再保存密钥或选择模型。只读取当前启用的 Codex 或 Claude；两者都有可用配置时优先 Codex。每次发送重新读取，当前动作全程使用同一份连接快照；读取失败会提示并停止使用旧连接。Web 的真实密钥只留在本机服务内存，浏览器仅保存跟随开关。普通远程托管页面和 `file://` 无法读取本机 CC Switch，设置中会显示本机增强版入口。

手动连接只需 URL 与 Key 即可保存；可获取模型列表并多选，也可添加准确模型标识，一个模型即可使用。顶栏切换模型对下一次请求生效。支持 Chat Completions、Responses 和 Anthropic Messages，需匹配服务的实际协议。

PDF / EPUB 依赖完整 `vendor/` 离线资源及本机 HTTP 服务，不能只分发 `index.html`。浏览器文档和批注保存在该地址的本地存储中，文件读写遵循浏览器授权；原生菜单和本机高召回检索仍由桌面版提供。原 `file://` 页面和不同端口各有独立存储，启动器不会迁移或清空旧页面数据。源码对齐记录与本轮验收见 [Web 版对齐记录](docs/Web版对齐与CC-Switch.md)。

```bash
node tools/sync-single-file.mjs
npm run test:regression:all
npm run build:mac
```

主页与智能研读另有浏览器验收分组，使用 Playwright 和 Chrome；模型回答为可控测试资料，不调用云模型。该分组独立于 `test:regression:all`，不会给原有回归增加浏览器依赖。本机可复用 bundled runtime 的 Playwright：

```bash
NODE_PATH="$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules" \
GUANYI_CHROMIUM_EXECUTABLE="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
npm run test:regression:workspace
```

该组当前含 `test:epub-review-integration` 和 `test:model-connection-browser`；纯 Node 的模型连接契约可单跑 `npm run test:model-connection`。

其他机器将 `NODE_PATH` 改为已安装 Playwright 的 `node_modules` 路径；也可通过 `GUANYI_PLAYWRIGHT_MODULE` 指定模块路径。浏览器结果只验证页面、PDF.js 与工作流，不能代替原生菜单、IPC、窗口关闭和安装包验收。原生 PDF 证据桥接使用 `npm run test:pdf-evidence-electron`，三工作区布局使用 `npm run test:desktop-layout-electron`。2026-11-13 已恢复本机 Electron 运行并通过原生阅读器、证据与布局专项；此前系统加载阶段的阻塞不再是当前结论。最新结果见[发布前体验清单](docs/发布前体验走查清单与矩阵验收.md)。

构建完成后，使用下面入口启动新 `.app` 验收主页与研读。默认运行 `release/mac-arm64/观译阅读器.app`，也可在命令末尾用 `-- "/绝对路径/观译阅读器.app/Contents/MacOS/观译阅读器"` 指定其他待验收包：

```bash
NODE_PATH="$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules" \
npm run test:packaged-home-study
```

该检查使用隔离测试资料及本地可控模型，经真实桌面 IPC 验证主页对话、PDF 页段提取、导读、学习卡、自测、来源问答、笔记和 Markdown 整理，再重启验证持久化。它同时核对应用版本，以及测试前后的应用 ASAR 和原 PDF 哈希；不替换已安装的应用，也不读取真实 API Key。此项验证包内真实工作流，不代表云模型的语义质量评分。

`js/app.js`、`css/app.css` 与阅读模块为可维护源码；主页位于 `js/home-workspace.js` / `css/home-workspace.css`，PDF 证据提取与研读位于 `js/pdf-evidence.js`、`js/pdf-study.js` / `css/pdf-study.css`。同步工具将这些模块和 `js/docs-data.js` 内置文档写入 `index.html`。桌面主进程与系统集成位于 `desktop/`，PDF.js、epub.js、JSZip 及许可证位于 `vendor/`。

构建使用项目内 `.cache/`；`build:*` 不改变版本号。正式发布须升级版本、完成完整回归并从干净提交构建，规范见[工程治理与桌面发布闸门](docs/工程治理与桌面发布闸门.md)。

安装包位于 `release/current/`，历史产物位于 `release/archive/`，构建验收位于 `release/build/`；这些目录不提交到 Git。
